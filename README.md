# Slideria — сайт и документация

## 1. Кратко о проекте

Сайт Slideria: презентации как данные, студия как PowerPoint, показ с окном докладчика и пультом, экспорт в один HTML, PowerPoint и PDF. Сделан на `Astro` с `TypeScript`, собирается в статические файлы.

Основные зоны:

* главная (`/`): живая витрина Slideria, студия, три способа сделать презентацию, показ и экспорт, каталог блоков, ИИ-агенты, программа для компьютера, облако;
* документация (`/docs/...`): для пользователей программы — что нажать, без команд и путей к файлам. Собирается из README и docs/ Slideria, две страницы написаны для сайта;
* демо-презентации (`/demo/*.html`): настоящие файлы, собранные Slideria.

**Облачная версия — отдельное приложение.** Сайт только ссылается на неё (`PUBLIC_CLOUD_URL`). Почему так и как связаны части: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## 2. Технологический стек

* `Astro 7`: статическая сборка, маршруты из файлов, коллекции контента
* `TypeScript 5`: строгий режим, проверка через `astro check`
* `Tailwind CSS 4` через `@tailwindcss/vite`
* `Shiki`: подсветка кода на этапе сборки, встроена в Astro
* `@lucide/astro`: иконки
* шрифты программы — Unbounded (заголовки) и Onest (текст): файлы из `@fontsource-variable`, подключены через API шрифтов Astro (предзагрузка и подогнанный запасной шрифт), без внешних CDN
* `sharp`: кадры слайдов в WebP, скриншоты — в AVIF и WebP нескольких ширин
* `@astrojs/sitemap`, `yaml`
* `Vitest` и `Playwright` — unit- и браузерные тесты

Интерактив (вкладки, тема, копирование, меню, каталог) написан на чистом TypeScript в `<script>` компонентов, без React: на главную уходит около 3 КБ своего JS (gzip). Если понадобится сложный интерактивный блок, его можно сделать React-островом через `@astrojs/react`.

Пакетный менеджер: `yarn` 1.x (`packageManager` зафиксирован в `package.json`).

## 3. Быстрый старт

Требования:

* `Node.js` 22.23 или новее (нужно для Astro 7)
* `yarn` 1.x

```bash
yarn install
yarn dev
```

Сайт откроется на `http://localhost:4321`.

```bash
yarn dev          # локальная разработка
yarn build        # сборка в dist/
yarn preview      # просмотр собранного dist/
yarn typecheck    # проверка типов (astro check)
yarn test         # unit-тесты, секунды
yarn test:e2e     # браузерные тесты на собранном сайте, около 40 с со сборкой
yarn perf         # плавность прокрутки (после yarn build)
yarn sync:engine  # забрать демо и документацию из репозитория Slideria
```

Переменные окружения: скопируйте `.env.example` в `.env`.

| Переменная | Что это |
|---|---|
| `PUBLIC_CLOUD_URL` | Адрес облака. Пока пусто, кнопки «Облако» ведут на `/#cloud` с пометкой «скоро» |
| `PUBLIC_DOWNLOAD_URL` | Ссылка на установщик для Windows. Пока пусто, кнопка «Программа для Windows» ведёт на `/docs/app` |
| `SITE_URL` | Публичный адрес сайта: sitemap, canonical, Open Graph |

## 4. Структура проекта

```
src/
  pages/              # маршруты: каждый файл — страница
  app/layouts/        # каркасы страниц: BaseLayout, SiteLayout, DocsLayout
  widgets/            # крупные блоки: шапка, подвал, секции главной, сайдбар документации
  entities/           # предметные блоки: deck (живые презентации), catalog (блоки из справочника),
                      # cloud (ссылка на облако), app (ссылка на установщик)
  shared/
    ui-kit/           # базовые компоненты: Button, CodeBlock, Logo, ThemeToggle…
    lib/              # конфиг, данные, клиентские скрипты
    styles/           # глобальные стили и токены темы
  content.config.ts   # коллекция документации
content/
  docs/               # страницы документации из README и docs/ Slideria (генерирует yarn sync:engine)
  guide/              # страницы документации, написанные для сайта: «Начало работы», «Подключить агента»
  catalog/            # справочник компонентов — данные для каталога блоков на главной
  decks/              # deck.yaml демо-презентаций: названия и заметки слайдов для вкладок и оглавления
  engine.json         # версия Slideria, из которой всё взято
src/assets/shots/     # скриншоты студии и программы, светлые и тёмные (режутся под экран при сборке)
public/
  demo/               # собранная витрина slideria.html
    posters/          # кадры слайдов и окна докладчика: показываются, пока презентация не запущена
scripts/
  sync-engine.mjs     # синхронизация с репозиторием Slideria
  lib/docs-transform.mjs  # документация разработчика → страницы для пользователей
  perf.mjs            # yarn perf
tests/
  unit/               # Vitest: фильтр документации, каталог, слайды демо, протокол окон, конфиг
  e2e/                # Playwright: главная, ссылки и якоря, «без ручек к коду», телефон
docs/
  ARCHITECTURE.md     # сайт, облако и программа: как разграничены
```

Что важно понимать по слоям:

* `pages`: только маршрутизация и сборка страницы из виджетов. Astro требует, чтобы маршруты лежали в `src/pages`.
* `app`: каркасы страниц и глобальная инициализация (тема без мигания, общие скрипты).
* `widgets`: композиционные блоки, собирают `entities` и `shared`.
* `entities`: блоки, привязанные к предмету: презентация, каталог, облако, установщик.
* `shared`: базовые кирпичики, которые можно использовать где угодно.

Импорт идёт сверху вниз: `pages → app → widgets → entities → shared`. Алиас `@/*` указывает на `src/*`.

## 6. Документация

**Документация — для пользователей программы, как в production.** В ней — что нажать в Slideria: студия, показ, импорт, экспорт, агенты. Команд терминала, путей к файлам репозитория, флагов, формата `deck.yaml` и устройства кода на сайте нет: с кодом работает разве что агент через MCP. За этим следит тест «документация говорит с пользователем» (`tests/e2e/site.spec.ts`).

| Страница | Откуда |
|---|---|
| Начало работы (`/docs`) | `content/guide/index.md` — написана для сайта |
| Во время показа | README Slideria → «Во время показа» |
| Студия | README → «Редактор (студия)» |
| Режим правки | README → «Режим правки» |
| Импорт | README → «Из PowerPoint», «Живые слайды», «Импорт правок из HTML-файла» + вступления в `scripts/sync-engine.mjs` |
| Агент в студии | `docs/AGENT.md` → «Где», «Сервисы», «Голос», «Дальше» |
| Подключить агента | `content/guide/mcp.md` — написана для сайта по `docs/MCP.md` |
| Что дальше | README → «Что дальше» |

Как из документации разработчика получается страница для пользователя (`scripts/lib/docs-transform.mjs`):

* блоки кода убираются целиком;
* абзац, пункт списка или строка таблицы, где в первом предложении есть ручка к коду (команда `yarn …`, путь в репозитории, файл, `deck.yaml`, «поле: значение», флаг, адрес с параметрами), уходят целиком, а если ручка дальше — уходит только это предложение, часть через «;» или скобки;
* разделы, от которых ничего не осталось, уходят вместе с заголовком;
* ссылки на файлы репозитория и на GitHub становятся текстом, на убранные разделы — тоже;
* длинные таблицы «что | как» на сайте показаны списком (`rehypeFeatureLists` в `astro.config.mjs`): на телефоне таблица с абзацами в ячейках не читается.

Чтобы обновить документацию и демо:

1. Поправить README или `docs/*.md` в репозитории Slideria (страницы из `content/guide/` правятся здесь).
2. Выполнить `yarn sync:engine` (репозиторий должен лежать рядом в `../HTMLPPTX`, иначе укажите `SLIDERIA_DIR=/путь`). Скрипт сам поставит зависимости программы без загрузки Electron, соберёт презентации и снимет кадры слайдов. Кадры снимает Playwright из репозитория Slideria: на Windows — установленным Microsoft Edge, как в его тестах; другой браузер — `SLIDERIA_CHROME=/путь/к/chrome`. Флаги: `--skip-build` — не пересобирать презентации, `--no-posters` — не снимать кадры.
3. Прогнать `yarn test` и `yarn test:e2e` и закоммитить изменения в `content/` и `public/demo/`.

Если в README программы появится новый раздел `##`, скрипт предупредит: решите, нужен ли он пользователям (`USED`), или это для разработчиков (`DEV_ONLY`).

## 7. Живые презентации на странице

На главной — настоящие файлы, собранные Slideria (`--clean --compact`: только показ, картинки в WebP). Они тяжёлые (витрина — 2,7 МБ) и крутят анимации в том же потоке, что и страница, поэтому **запускаются только по щелчку**. До этого вместо них — кадры слайдов из `public/demo/posters/`:

* `DeckShowcase` (первый экран): окно браузера с кадром слайда и вкладки слайдов под ним. Вкладки и автопрокрутка листают кадры; «Запустить показ» (или щелчок по кадру) открывает саму витрину на том же слайде, дальше всё листается синхронно. Кода на первом экране нет — ни YAML, ни имён файлов данных;
* `PresenterPreview`: кадр окна докладчика, по щелчку — настоящее окно. Оно само находит запущенную витрину на первом экране через `BroadcastChannel` и листается вместе с ней;

Управление идёт тем же протоколом, которым Slideria связывает окно показа и окно докладчика: [`src/entities/deck/lib/protocol.ts`](src/entities/deck/lib/protocol.ts). Тема сайта передаётся в презентации, ключ в `localStorage` у них общий.

Каталог блоков на главной (`src/entities/catalog/readCatalog.ts`) собирается из справочника компонентов (`content/catalog/components.md`): новые блоки в Slideria появляются на сайте сами после `yarn sync:engine`. На карточках — названия и описания без имён полей; где справочник начинается с примера или описание звучит как код, подпись задана в `OVERRIDES`, стили презентации (CSS) в каталог не попадают (`EXCLUDE`).

Какие презентации забирать, задаёт переменная `DECKS` (по умолчанию `slideria`).

Скриншоты студии и программы в `src/assets/shots/` сняты с настоящей программы на витрине Slideria (1440 × 900, ×2, WebP); компонент `Shot` отдаёт их в AVIF и WebP нескольких ширин. При заметных изменениях интерфейса их стоит переснять.

## 8. Тесты

```bash
yarn test       # unit (Vitest), меньше секунды
yarn test:e2e   # браузерные (Playwright): сам собирает сайт и поднимает его на порту 4329
```

Браузер для `test:e2e` и `perf`: на Windows — установленный Microsoft Edge (качать ничего не нужно), на macOS и Linux — один раз `npx playwright install chromium`; другой — `LANDING_TEST_BROWSER=chrome`. Тестовый сервер поднимается рядом, даже если открыт обычный `yarn preview`. Упавший тест оставляет снимок в `.tmp/test-results`.

| Набор | Что ловит |
|---|---|
| unit · документация | что считается ручкой к коду и что нет; убираются предложения, строки, пустые разделы и таблицы, а заголовки с текстом остаются; ссылки на GitHub и файлы — текстом |
| unit · каталог | в подписях блоков нет кода, CSS исключён, порядок групп |
| unit · слайды демо | слайдов столько же, сколько в сборке; у каждого название |
| unit · протокол окон | конверт с отправителем (без него новый движок падает); чужие сообщения и сообщения другому окну отбрасываются |
| unit · конфиг | ссылки на облако и установщик с адресами и без; размер файла по-русски |
| e2e · главная | при загрузке нет фреймов; на первом экране нет кода; кадр витрины виден сразу и после смены вкладки; вкладки листают кадры; показ запускается на том же слайде и синхронизирован в обе стороны; тема, окно докладчика, каталог |
| e2e · сайт | все ссылки и якоря целы; ссылок на GitHub нет; в документации нет команд, путей и флагов; у каждой страницы заголовок и пункт меню; 404; sitemap и robots |
| e2e · телефон | ни одна страница не прокручивается вбок; меню открывается и закрывается |

## 9. Скорость

Замеры — на собранном сайте (`yarn build && yarn preview`), не в `yarn dev`: в режиме разработки модули и стили грузятся по одному, а Markdown документации подсвечивается заново на каждый запрос, и страница заметно медленнее. Плавность прокрутки — `yarn perf`, баллы Lighthouse — в Chrome: DevTools → Lighthouse.

| | Было | Стало |
|---|---|---|
| Lighthouse, телефон: производительность | 44 | 98–100 |
| FCP / LCP, телефон | 6,8 с / 8,8 с | 0,9 с / 0,9 с |
| TBT, телефон | 590 мс | 70–150 мс |
| Lighthouse, компьютер | 75 | 100 |
| Прокрутка, процессор ×4 медленнее: медиана кадра | 33 мс | 17 мс |
| Кадров дольше 50 мс за прокрутку страницы | 48 | 0 |

Доступность, лучшие практики и SEO — по 100 на главной и в документации.

Правила, на которых это держится:

* **Тяжёлое — по щелчку.** Живые презентации и всё, что крутит свой движок, не запускаются сами: сначала кадр.
* **Без `filter: blur` на больших элементах и без `backdrop-filter`.** Мягкие пятна — радиальным градиентом, шапка — почти непрозрачным фоном.
* **Бесконечные анимации — только `transform` и `opacity`** (их двигает видеокарта) и только в секциях с атрибутом `data-anim`: за экраном такая секция получает `data-paused`, и анимации стоят (сам атрибут `data-paused` не ставить ни на что, где появление начинается с прозрачности: оно замрёт невидимым). Звёзды — одна статичная картинка.
* **Ничего не анимировать по `letter-spacing`, `filter`, размерам и положению** (`left`, `width`…) — это пересчёт раскладки или перерисовка на каждом кадре. Бегущая точка двигает дорожку во всю ширину через `transform`.
* **Сцена первого экрана** (`StageBackdrop`) — сияние, луч, пол-сетка и зерно: сияние дрейфует `transform`, луч «дышит» `opacity`, зерно — готовая картинка `public/textures/grain.png`, а не SVG-фильтр (тот рисуется на основном потоке). На телефоне пола нет, сияние стоит.
* **Шрифты** — через API шрифтов Astro: запасной шрифт с подогнанными метриками, поэтому текст не прыгает, когда шрифт загрузился. Предзагружается только Unbounded (заголовки).
* **Картинки** — с `width`/`height`, `loading="lazy"`, скриншоты — через `Shot` (AVIF и WebP под ширину экрана). Скрытый кадр другой темы не загружается.
* **Стили — в HTML** (`build.inlineStylesheets: 'always'`): на первый показ не нужен отдельный запрос.

## 10. Стили и тема

* Utility-классы Tailwind прямо в разметке.
* Цвета только через токены из `src/shared/styles/globals.css`: `bg-surf`, `text-tx`, `border-bd`, `text-ac`… Имена совпадают с токенами Slideria. Второй акцент — розовый `--pk`, как у витрины.
* Заголовки — `font-display` (Unbounded), текст — Onest.
* Тёмная тема: атрибут `data-theme` на `<html>`. Его ставит скрипт до первой отрисовки (по выбору пользователя или по системе), вариант `dark:` в Tailwind привязан к нему. Скриншоты переключаются вместе с темой.
* Появление при прокрутке: атрибут `data-reveal`. Без JS всё видно сразу.
* Раздел «Облако» всегда тёмный, как шаблон `space`.
* Первый и финальный экраны — «сцена» (`src/shared/ui-kit/StageBackdrop.astro`): сияние, луч прожектора, пол-сетка у первого экрана, плёночное зерно. Окно витрины — со светом, бегущим по кромке (`.showcase-frame`, `.showcase-edge`), и отсветом под ним. В тёмной теме всё ярче.

## 11. Конфигурация

* `astro.config.mjs`: адрес сайта, sitemap, Tailwind, шрифты, стили в HTML, длинные таблицы документации — списком.
* `src/content.config.ts`: схема коллекции документации.
* `src/shared/lib/config.ts`: название, адреса облака и установщика, версия Slideria.
* `tsconfig.json`: строгий TypeScript и алиас `@/*`.

## 12. Практические сценарии

**Добавить секцию на главную**

1. Создать `src/widgets/home/<Name>.astro`.
2. Подключить в `src/pages/index.astro`.
3. При необходимости добавить пункт в `mainNavLinks` (`src/shared/lib/data/mainData.ts`).

**Добавить обычную страницу**

1. Создать `src/pages/<route>.astro` и обернуть в `SiteLayout`.
2. Собрать страницу из `widgets`, `entities` и `shared`.

**Добавить ссылку в облако**

```astro
<CloudLink path="/new?template=basic" label="Открыть в облаке" />
```

**Обновить демо и документацию**: `yarn sync:engine`, потом `yarn test` и `yarn test:e2e`.

**Куда класть новый блок**

1. Крупный, собирает несколько блоков → `widgets/`.
2. Привязан к предмету (презентация, облако, тарифы) → `entities/<domain>/`.
3. Базовый элемент: кнопка, бейдж, блок кода → `shared/ui-kit/`.

## 13. Деплой

`yarn build` кладёт готовый сайт в `dist/`: обычные HTML-, CSS- и JS-файлы. Подходит любой статический хостинг: nginx на своём сервере, Cloudflare Pages, S3 + CDN. Серверная часть не нужна.

Перед сборкой задайте `SITE_URL`, а когда появятся — `PUBLIC_DOWNLOAD_URL` и `PUBLIC_CLOUD_URL`.
