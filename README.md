# HTMLPPTX — лендинг и документация

## 1. Кратко о проекте

Сайт движка HTML-презентаций [HTMLPPTX](https://github.com/kotomoran070-source/HTMLPPTX). Сделан на `Astro` с `TypeScript`, собирается в статические файлы.

Основные зоны:

* главная (`/`): одностраничник с живым демо, возможностями, каталогом компонентов, примером и разделом про облако;
* документация (`/docs/...`): собирается из README и справочника компонентов движка;
* демо-презентации (`/demo/*.html`): настоящие файлы, собранные движком.

**Облачная версия — отдельное приложение.** Лендинг только ссылается на неё (`PUBLIC_CLOUD_URL`). Почему так и как связаны части: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## 2. Технологический стек

* `Astro 7`: статическая сборка, маршруты из файлов, коллекции контента
* `TypeScript 5`: строгий режим, проверка через `astro check`
* `Tailwind CSS 4` через `@tailwindcss/vite`
* `Shiki`: подсветка кода на этапе сборки, встроена в Astro
* `@lucide/astro`: иконки
* `@fontsource-variable`: шрифты Manrope и JetBrains Mono лежат в сборке, без внешних CDN
* `@astrojs/sitemap`, `yaml`, `qrcode-generator`

Интерактив (вкладки, тема, копирование, меню) написан на чистом TypeScript в `<script>` компонентов, без React. На главную уходит около 2 КБ JS (gzip). Если понадобится сложный интерактивный блок, его можно сделать React-островом через `@astrojs/react`.

Пакетный менеджер: `yarn` 1.x (`packageManager` зафиксирован в `package.json`).

## 3. Быстрый старт

Требования:

* `Node.js` 22.23 или новее (нужно для Astro 7)
* `yarn` 1.x

```bash
yarn install
yarn dev
```

Сайт откроется на `http://localhost:4321`.

```bash
yarn dev          # локальная разработка
yarn build        # сборка в dist/
yarn preview      # просмотр собранного dist/
yarn typecheck    # проверка типов (astro check)
yarn sync:engine  # забрать демо и документацию из репозитория движка
```

Переменные окружения: скопируйте `.env.example` в `.env`.

| Переменная | Что это |
|---|---|
| `PUBLIC_CLOUD_URL` | Адрес облака. Пока пусто, кнопки «Облако» ведут на `/#cloud` с пометкой «скоро» |
| `SITE_URL` | Публичный адрес лендинга: sitemap, canonical, Open Graph |

## 4. Структура проекта

```
src/
  pages/              # маршруты: каждый файл — страница
  app/layouts/        # каркасы страниц: BaseLayout, SiteLayout, DocsLayout
  widgets/            # крупные блоки: шапка, подвал, секции главной, сайдбар документации
  entities/           # предметные блоки: deck (живые презентации), cloud (ссылка на облако)
  shared/
    ui-kit/           # базовые компоненты: Button, CodeBlock, Logo, ThemeToggle…
    lib/              # конфиг, данные, клиентские скрипты
    styles/           # глобальные стили и токены темы
  content.config.ts   # коллекция документации
content/
  docs/               # страницы документации (генерирует yarn sync:engine)
  decks/              # deck.yaml демо-презентаций (для показа кода)
  engine.json         # версия движка, из которой всё взято
public/
  demo/               # собранные презентации: tour.html, microclimate.html
scripts/
  sync-engine.mjs     # синхронизация с репозиторием движка
docs/
  ARCHITECTURE.md     # лендинг, облако и движок: как разграничены
```

Что важно понимать по слоям:

* `pages`: только маршрутизация и сборка страницы из виджетов. Astro требует, чтобы маршруты лежали в `src/pages`.
* `app`: каркасы страниц и глобальная инициализация (тема без мигания, общие скрипты).
* `widgets`: композиционные блоки, собирают `entities` и `shared`.
* `entities`: блоки, привязанные к предмету: презентация движка, облако.
* `shared`: базовые кирпичики, которые можно использовать где угодно.

Импорт идёт сверху вниз: `pages → app → widgets → entities → shared`. Алиас `@/*` указывает на `src/*`.

## 5. Маршрутизация

| Файл | Адрес |
|---|---|
| `src/pages/index.astro` | `/` |
| `src/pages/docs/[...slug].astro` | `/docs`, `/docs/components`, `/docs/show`… |
| `src/pages/404.astro` | страница «не найдено» |
| `src/pages/robots.txt.ts` | `/robots.txt` |

`sitemap-index.xml` генерирует `@astrojs/sitemap`.

## 6. Документация

Документация не пишется вручную. Источник правды — репозиторий движка:

* `README.md` движка делится по заголовкам `##` на страницы. Какой раздел на какую страницу попадает, задаёт таблица `PAGES` в `scripts/sync-engine.mjs`;
* `docs/COMPONENTS.md` становится страницей `/docs/components`;
* заголовок вида ``### `grid` — сетка`` получает якорь `#grid`, на него ссылается каталог компонентов на главной.

Чтобы обновить документацию:

1. Поправить README или COMPONENTS.md в репозитории HTMLPPTX.
2. Выполнить `yarn sync:engine` (движок должен лежать рядом в `../HTMLPPTX`, иначе укажите `HTMLPPTX_DIR=/путь`).
3. Закоммитить изменения в `content/` и `public/demo/`.

Если в README движка появится новый раздел `##`, скрипт предупредит: добавьте его в `PAGES`.

## 7. Живые презентации на странице

На главной работают настоящие файлы, собранные движком, а не скриншоты:

* `DeckStudio` (первый экран): слева YAML слайда, справа презентация. Вкладки, автопрокрутка и сама презентация листаются синхронно;
* `PresenterPreview`: настоящее окно докладчика движка. Оно само находит презентацию на первом экране через `BroadcastChannel` и листается вместе с ней;
* `DeckViewer`: пример отчёта с оглавлением.

Управление идёт тем же протоколом, которым движок связывает окно показа и окно докладчика: [`src/entities/deck/lib/protocol.ts`](src/entities/deck/lib/protocol.ts). Тема сайта передаётся в презентации, ключ в `localStorage` у них общий (`htmlpptx-theme`).

Какие презентации забирать, задаёт переменная `DECKS` (по умолчанию `tour,microclimate`). Демо `tour` лежит в репозитории движка: `presentations/tour/deck.yaml`.

## 8. Стили и тема

* Utility-классы Tailwind прямо в разметке.
* Цвета только через токены из `src/shared/styles/globals.css`: `bg-surf`, `text-tx`, `border-bd`, `text-ac`… Имена совпадают с токенами движка.
* Тёмная тема: атрибут `data-theme` на `<html>`. Его ставит скрипт до первой отрисовки (по выбору пользователя или по системе), вариант `dark:` в Tailwind привязан к нему.
* Появление при прокрутке: атрибут `data-reveal`. Без JS всё видно сразу.
* Раздел «Облако» всегда тёмный, как шаблон `space` у движка.

## 9. Конфигурация

* `astro.config.mjs`: адрес сайта, sitemap, Tailwind, темы подсветки кода, якоря для справочника компонентов.
* `src/content.config.ts`: схема коллекции документации.
* `src/shared/lib/config.ts`: название, ссылки, адрес облака, версия движка.
* `tsconfig.json`: строгий TypeScript и алиас `@/*`.

## 10. Практические сценарии

**Добавить секцию на главную**

1. Создать `src/widgets/home/<Name>.astro`.
2. Подключить в `src/pages/index.astro`.
3. При необходимости добавить пункт в `mainNavLinks` (`src/shared/lib/data/mainData.ts`).

**Добавить обычную страницу**

1. Создать `src/pages/<route>.astro` и обернуть в `SiteLayout`.
2. Собрать страницу из `widgets`, `entities` и `shared`.

**Добавить ссылку в облако**

```astro
<CloudLink path="/new?template=tour" label="Открыть в облаке" />
```

**Обновить демо-презентации**: поправить `deck.yaml` в движке, выполнить `yarn sync:engine`.

**Куда класть новый блок**

1. Крупный, собирает несколько блоков → `widgets/`.
2. Привязан к предмету (презентация, облако, тарифы) → `entities/<domain>/`.
3. Базовый элемент: кнопка, бейдж, блок кода → `shared/ui-kit/`.

## 11. Деплой

`yarn build` кладёт готовый сайт в `dist/`: обычные HTML-, CSS- и JS-файлы. Подходит любой статический хостинг: nginx на своём сервере, Cloudflare Pages, GitHub Pages, S3 + CDN. Серверная часть не нужна.

Перед сборкой задайте `SITE_URL` и, когда облако заработает, `PUBLIC_CLOUD_URL`.
